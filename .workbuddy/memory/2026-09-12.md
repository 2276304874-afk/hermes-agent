## 首字延迟 45s 归因（P0-1 实测·结案）

### 结论：100% 是 system prompt 的 prefill 成本，不是编排/网络/会话/模型推理
外部探针（/tmp 下只读，生产代码零改动）三分法：
- HTTP 首字节 80ms · ready@48ms · session@63ms · 首个 msg@215ms → **前置全链路仅 215ms**
- 然后 **黑洞 23.7s**，才到首个 token@23992ms
- createSession 单独 13ms（不是瓶颈）· Ollama 原生小 prompt 首字节 526ms（地基很快）

Hermes 自己日志给出 smoking gun：
```
API call #1: in=15612 out=188 latency=23.9s cache=15607/15612 (100%)
```
问两个字，prompt 却 **15612 token**（占 context_length 16384 的 **95%**）。

### 因果验证：prefill 长度 → 首 token 延迟，严格线性
```
   20 tok →   416ms
 2082 tok →  7339ms
 4175 tok →  7945ms
 8373 tok → 17752ms
16374 tok → 42857ms
```
拟合：**latency ≈ 2.3 ms/token × N + ~3.9s 固定开销**。
15612 落此区间，与 Hermes 的 23.9s 同量级 → 因果坐实。

### 推论：目标延迟 ↔ prompt 预算（硬约束）
- 10s → N ≤ **~2650**（需削减当前 **83%**）
- 8s  → N ≤ ~1780
- 5s  → N ≤ ~480 ← **不可行**，system prompt 本身不止这么多
⚠️ 故「压缩到 10s 内」是激进目标，现实目标定 **8–15s**。

### 优化杠杆（均在 ~/.hermes/config.yaml，非本仓库代码）
1. **削减 system prompt**（唯一根因，15612 → 数千）
   - ⚠️ 现配置 `tools.tool_search.enabled: off`。注释理由是「避免模型把原生工具误当成 bridge 调用」，
     但代价是**所有原生工具定义必须全量注入 prompt**。开 tool_search 可让工具定义按需加载
     （`build_catalog_listing` 有 max_tokens=4000 预算 + 三级降级）。**这是最大单一杠杆，但与原注释决策冲突，须重测工具调用正确性。**
   - `~/.hermes/skills` 有 **100 个 skills / 46MB**，若参与 System Prompt 即为大头
   - 日志里见到 `[自动召回的相关历史经验...]` 被注入，且内容很长 → 记忆召回也占量
2. **关 auxiliary title_generation**：每轮额外起一次本地模型调用，**抢占同一个 Ollama 实例**，
   且日志显示它反复 timeout+retry。而我们 chat.js 已自带唯一标题生成 → **纯重复浪费**。
3. **关云端 auxiliary fallback**（openrouter/nous）：日志每轮都 mark unhealthy，
   隐私红线本就不接云端，纯耗时。
4. **micro_compact 的假设已被证伪**：config 注释称「本地模型无缓存成本」，但实测 prefill
   就是实打实的成本（2.3ms/tok），且每回合压缩会破坏 prefix 稳定性（Ollama prompt cache 依赖稳定前缀）。

### ❗ 延迟的真正敏感项：prompt cache 前缀命中率（新发现，高于 prompt 长度）
同一 Hermes 日志里三种 latency 并列出现：
```
cache=100% → latency=6.5s
cache=100% → latency=23.6s
cache= 97% → latency=34.7s     ← 前缀失配 → 5 倍差异
```
KV cache 必须前缀**完全一致**才能复用，失配则从失配点起重算，
故 `micro_compact_every_n_turns: 1`（每回合压缩改写前缀）是 cache 的头号破坏者。
→ 后续削减 prompt 时，**优先保证前缀稳定**，其次才是缩短长度。

### 附带修掉一个严重回归（gateway 切换以来一直坏着）
同一份会话 ID 格式约束写了两份且不同步：config.js（路由校验）+ parse.js（解析）。
gateway 的会话是 `api_<10位>_<8位hex>`，只在解析侧补了 → 于是
`/api/session/{rename,delete,export}` 与 `/api/workspace/assign` 对**全部** gateway 会话返 400，
且 /api/sessions 判 degraded。修复：正则支持三种形态；收敛为单一真源在 parse.js
（config 反向依赖 parse，反向引入会成循环依赖），config 转出，路由零改动。
列表分列改用 /\s{2,}/（定宽表格用多空格填充列间距，正文内部单空格）——
原先按 \s+ 切会把标题拦腰截断，使特意加的 #runId 去重后缀在界面上完全看不见。
