# OpenClaw 与 赫尔墨斯特工 · 系统对比

> 对比日期：2026-09-13
> 方法：OpenClaw 侧取公开资料（官方站 / GitHub / NVD-CVE / 权威媒体）核实；特工侧取本项目代码与运行态实测（后端 4,818 行 + 前端 3,170 行，0 npm 依赖，194 个技能，56 个 API 端点，65 次提交）。

---

## 0. TL;DR：一句话定位差异

- **OpenClaw = 面向大众与企业的开源自托管 Agent 平台**（自称"AI Agent 的操作系统"）。目标是让百万级用户拥有"住在聊天软件里的 AI"，**以渠道触达和技能生态取胜，安全是事后补的**。
- **赫尔墨斯特工 = 单人私有、本地优先的深度定制特工**。目标是"在我的机器上、我的数据不出门"的前提下，把大模型变成可行动、可记忆的助手，**以可控、可审计、可复现取胜，生态需要自建**。

一句话：**OpenClaw 是"给所有人的 Agent 操作系统"，特工是"给我自己的 Agent 内核"。**

## 3. 工作原理

### 3.1 OpenClaw
```
消息渠道(20+) ──► WebSocket Gateway 守护进程(127.0.0.1:18789，JSON-Schema 校验)
                        │ 统一调度 · 控制平面跑在用户设备
                        ▼
                  Agent Runtime ──► 任意前沿/本地模型
                        │
        ┌───────────────┼────────────────┐
        ▼               ▼                ▼
   技能(markdown)   心跳调度器        持久记忆文件
   ClawHub 市集     自主节奏触发      (SOUL.md 等)
```
- **TS 运行时**，Gateway 是中心化的常驻守护进程，所有渠道消息经它统一路由。
- 技能是 markdown 描述的能力包，可热插拔；**从开放市集安装**。
- 心跳让 Agent 不必等人 prompt 就能自己动起来。
- 信任边界在"运行时流入的任何内容"——这也是它安全问题的**架构根因**。

### 3.2 赫尔墨斯特工
```
浏览器(Web UI :4173) ──► Node UI 后端(零依赖，launchd 托管)
                              │ Bearer 鉴权 · SSE 流式
                              ▼
                   双后端（同构 gateway 思路）
                   ├─ oneshot Hermes CLI(-z)   ├─ gateway(:8642) + api_server 适配器
                              │
        ┌─────────────┬───────┴──────┬─────────────┐
        ▼             ▼              ▼             ▼
   本地 Ollama     SKILL.md(194)   影子 git 检查点   safety hook
   模型常驻        渐进式加载        回滚(双守卫)      三色权限(fail-closed)
```
- 每轮**按需 spawn 引擎**（非常驻），进度靠 state.db 轮询 + token 流双通道。
- 技能**渐进式加载**（索引只注入摘要，命中才读全文），控制上下文预算。
- 检查点用**跨项目去重的影子 git 库**，回滚有双守卫（须注册项目 + 提交须在 ref 历史）。
- 出网面为零：本地模型、无云 key。

**关键工程差异**：OpenClaw 是"常驻守护进程 + 长连接控制面"，特工是"按需短进程 + 轮询/SSE"。前者实时性与渠道并发更好，后者资源占用低、崩溃面小、可审计。

## 4. 优缺点

### 4.1 OpenClaw
**优点**
- 渠道成熟度无人能及（20+ 平台，一体化接入）。
- 技能生态最大（ClawHub 数千技能 + 2,500 贡献者）。
- 心跳自主调度，真正"数字员工"形态。
- 跨平台（mac / win / linux）、Docker、一键安装。
- 上游活跃、增长最快（2026-08 约 **384,992** 星，GitHub 全站第 6）。

**缺点**
- **安全事故灾难级**：CVE-2026-25253「ClawJacked」零点击 WS 劫持（CVSS 8.8）+ 命令注入 / SSRF / 路径穿越 / prompt-injection→RCE；公网裸奔实例 **15.5 万+**。
- **供应链投毒**：ClawHub 2,857 技能中 341 恶意（335 装 macOS 窃密软件）；全市场 **12–36% 含 prompt injection**。
- **持久化后门**：记忆文件（SOUL.md）可被写入，重启存活。
- **运维门槛高**：实测 15h+ setup，"太贵、太慢、不够可靠"是常见评价，更适合技术人。
- 依赖 TS 生态，需构建；数十万行代码难以通读审计。

### 4.2 赫尔墨斯特工
**优点**
- **安全模型成熟**：loopback 绑定 + Bearer 鉴权 + 三色权限 + safety hook + 检查点回滚——正好堵住 OpenClaw 那一类坑。
- **0 依赖、~8K 行**，可通读、可审计、可复现（换机 `setup.sh` 幂等重放）。
- **数据零出网**：本地 Ollama、无云 key、无外部记忆系统。
- **跨 Agent 经验沉淀**（KB 知识库）——OpenClaw 没有的独有能力。
- **对话 / 工作双模式**；中文本地优先。
- 体量小、改动快（本次审计一天内闭环 10 项缺陷）。

**缺点**
- **触达窄**：只有 Web UI，没有 IM 渠道（Telegram 等未接）。
- **单机单用户**：无多租户、无团队协作、无远程接入。
- **无生态**：技能靠自建，没有社区市集与人共享。
- **模型能力受硬件限制**：16GB 机器上只能用 4B–8B 级本地模型，推理深度不如云端前沿模型。
- **bus factor = 1**：单一维护者，无社区兜底。

## 5. 异同点总结

### 相同（理念层，说明方向被验证）
1. **本地优先**：数据与配置归用户，控制平面跑在本地设备。
2. **Gateway 中枢**：所有请求经统一网关调度（特工是 server.js + gateway，同构思路）。
3. **可组合工具 + 技能系统 + 持久记忆**：三件套齐全。
4. **开源 / 自持**：都能拿到源码、自主修改。
5. **从"对话"到"行动"**：都定位成能执行任务的 Agent，而非聊天机器人。

### 不同（工程 / 产品层）
| 分野 | OpenClaw | 赫尔墨斯特工 |
|---|---|---|
| 规模 | 数十万行 TS，生态工程 | ~8K 行 Node，0 依赖 |
| 渠道 | 20+ IM 平台 | Web UI |
| 模型方向 | 云端为主 | **本地优先（方向相反）** |
| 安全 | 事后补丁，事故频发 | **原生防线，领先一代** |
| 生态 | 开放市集（也是风险源） | 自持白名单（安全但闭塞） |
| 记忆 | 通用记忆文件 | MEMORY.md + **跨 Agent KB** |
| 用户 | 百万级大众/企业 | 单人 |
| 治理 | 基金会 + 社区 | 单一维护者 |

## 6. 适用建议

### 6.1 选 OpenClaw，如果你：
- 需要**接入大量聊天平台**（WhatsApp/Telegram/Discord…），要 Agent 住在你已有的 IM 里。
- 想要**现成的技能生态**，不介意从开放市集装东西。
- 需要**团队/多人协作**或多设备触达，能接受加固运维成本。
- **前提（强烈建议）**：不要用主账号、隔离到专用 VM、只给非特权凭证、**绝不暴露公网**、第三方技能先审计。默认部署不适合碰敏感数据。

### 6.2 继续自建特工，如果你：
- 要**绝对本地与隐私**，数据/凭证不出门、无云 key。
- 要**可通读、可审计**的极小代码面，能自己掌控每一行。
- 需要**深度定制**（专属技能、双模式、KB 沉淀），愿意自己养。
- 单人使用为主，不需要 IM 触达。
- **前提**：接受模型能力受本地硬件限制，接受没有现成生态。

### 6.3 混合路线（推荐）
- **主体继续用特工**：安全底座与本地推理是你的护城河。
- **只借鉴 OpenClaw 的"机制层"**：
  1. **渠道抽象层**——为将来接 Telegram/Webhook 预留 adapter 接口。
  2. **技能机制**——吸收其 markdown 热插拔的便利，但**坚持白名单 + 自托管，绝不引入开放市集**。
  3. **长连接控制面**——评估 WS 替代 state.db 轮询，降低首字延迟与 CPU。
- **安全模型反过来**：拿 OpenClaw 的 CVE 清单当"必须自查项"对照表，而非参考实现。

---

## 7. 结论

**不需要换用它。** 特工是"本地模型版的 OpenClaw"，而且在**安全成熟度上比它领先一代**——本次审计加固的防线（loopback + 鉴权 + 三色权限 + safety hook + 检查点），恰恰就是 OpenClaw 缺失、并被 NVIDIA NemoClaw 事后补救的那一类。

OpenClaw 真正的价值是**参照系**：它的渠道成熟度、技能机制、心跳调度是社区打磨过的，值得在"触达扩展"规划里借鉴思路；**但它的安全记录是反面教材，不可照搬。**

一句话建议：**产品形态看 OpenClaw，安全基线看自己。**
