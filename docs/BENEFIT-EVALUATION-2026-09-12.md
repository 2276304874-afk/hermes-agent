## 1. 收益定义与计算口径

### 1.1 统一度量
本地优先 AI 工具的"收益"无直接营收，统一折算为两类可比较的量：

- **等效人工分钟/月（EMM）**：本项收益相当于每月为人省下多少分钟的人工操作或恢复成本。
- **收益点（BP，0–100）**：对"风险消除 / 能力增益 / 成本规避"三类的综合定性评分，用于跨对象排序。

### 1.2 收益构成
```
B = 风险消除价值 + 能力增益价值 + 成本规避价值
```
- **风险消除价值**：`P(事件/月) × 单次恢复 EMM`，含不可恢复情形的尾部风险（灾难级，权重更高）。
- **能力增益价值**：新能力可用频率 × 单次价值；零额外运行时成本的能力额外加分。
- **成本规避价值**：本项避免的重复计算 / 重复推送 / 重复排查成本。

### 1.3 校准锚点（取自真实项目事实，非拍脑袋）
| 锚点 | 对应事实 | 折算 |
|---|---|---|
| H（BP 80–100） | 消除「确定性不可恢复风险」或削减 #1 痛点（首字 45s）>30% | 高 |
| M（BP 40–70） | 新增近零运行时成本的护栏 / 补上"重装即失效"的可复现性缺口 | 中 |
| L（BP 10–35） | 锦上添花 UX / 收益未经证实的优化 | 低 |

### 1.4 成本档（C）与 ROI
| 档 | 含义 | 典型耗时 |
|---|---|---|
| C1 | 验证 / 文档 / 小改 | < 2h |
| C2 | 新模块 + 测试 | 2–6h |
| C3 | 重 profiling / 外部依赖 / 需用户动作 | > 6h 或阻断 |

```
ROI = BP / 成本档权重（C1=1, C2=2.5, C3=5）
```
ROI ≥ 40 视为"应立即做"；20–40 "排期做"；< 20 "挂起"。

## 4. 潜在风险与限制条件

1. **launchd EIO 边界（A2 阻断项）**：我的 shell 注册/启动 launchd 必 EIO 5，A2 的最终验证必须你在 Terminal.app 手动跑一次 `setup.sh`，我只能产出 diff 并自检"只增不减"。
2. **配置在仓库外（A2 根源）**：`checkpoints.*` / `terminal.cwd` / gateway key 均在 `~/.hermes/config.yaml`，`git` 不追踪 → 重装即丢失；防漂移仅靠 `npm run health` §10 断言 + hermes 快照。
3. **镜像无增量（成本约束）**：每次整体重推 723–756 调用 / ~8 分钟。频繁推送不经济 → 攒一批再推；判据只能比根树 sha（提交 sha 必不同）。
4. **prompt-cache 脆弱性（全局约束）**：技能索引字节一变 → 前缀失效 → 单请求 +28s。任何"动态索引"必须保证字节稳定，否则反向劣化。
5. **裁判尚未实证（A1 即为此缺口）**：确定性判据逻辑完备，但没用真实"打转"样本复测过；误报/漏报的真实分布未知。
6. **单模型 4B 天花板**：限制裁判可靠性，也限制"LLM 冷裁判"方案（原审计推荐，本轮已弃用）；护栏只能靠确定性规则。
7. **上下文 32K 仅够用**：静态 prompt ≈17K tok 起步，新增工具/扩 system 有爆预算风险（曾因 16K 窗口导致模型失忆写 hello-world）。
8. **工具实时性限制（本报告撰写时）**：Bash 在工具层临时不可用，实时指标沿用本会话早前实测；不影响结论，但下次跑 A1 复测时应重新拉 `/api/usage` 确认基线未漂移。

## 5. 评估结论

- **已落地三项均达"高收益"预期**：检查点回退（BP 85）与异地镜像（BP 80）属"消除确定性风险"类，收益最实、最可量化；停止裁判（BP 60）是零运行时成本的常驻护栏，收益偏"防患"。
- **待投资中 A1 是性价比之王**：成本≈0、直接补唯一验证缺口，ROI 全场最高，且无破坏性。
- **A2 收益高但卡在"需用户动作"**：可复现性缺口真实存在，解法清晰，唯一阻塞是 launchd 边界——这是流程问题不是技术难题。
- **P2-3 是"收益天花板最高、确定性最低"的对象**：45s 痛点真实，但根因未定位前任何优化都可能是空转；建议列为"先 profiling 后投入"，不要现在动手。
- **整体建议节奏**：先 A1（我独立完成）→ 与你确认 A2 的 `setup.sh` diff 并由你跑一次 → B1/C2 排期 → P2-3 立项 profiling。

## 6. 优化建议（按 ROI 排序）

1. **【立即】跑 A1 裁判复测**：用固定反例集（重复同工具调用、同结果复现）触发 judge 事件，确认前端 `⚖️` 渲染与 `HERMES_JUDGE_ABORT` 行为符合预期。成本≈0。
2. **【本周】A2 配置真源落盘**：我改 `setup.sh` 幂等补写 `checkpoints.*` 与 `terminal.cwd`，先 `cp` 备份 config.yaml，diff 校验"只增不减"，再请你在 Terminal.app 跑 `bash setup.sh` 一次确认；healthcheck §10 即转型为"重装自检"。
3. **【排期】C2 拦截反馈可读化**：把危险命令放行后的提示从技术态改成用户可读态，保留 TTL 语义。
4. **【排期】B1 curator adopt**：先读 `curator` 源码确认副作用，副本 dry-run，确认能去重/清孤儿 embeddings 且不破坏在用技能再正式 adopt。
5. **【立项不急于做】P2-3 延迟优化**：先加打点定位 45s 拆解（createSession / 工具注册 / gateway 编排各占多少），再决定杠杆点；严禁未 profiling 先优化。
6. **【工程纪律】保护 prompt cache**：任何改技能索引/系统 prompt 前缀的变动，先测 cache 命中率（100%→6.5s vs 97%→34.7s），字节稳定优先。
7. **【工程纪律】镜像攒批推**：仅在"完成一批可提交改动"后推一次；判据只看根树 sha，勿因 `git status` 显示 diverged 误判。
