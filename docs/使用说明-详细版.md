# 赫尔墨斯特工 · 使用说明（详细版）

> 面向使用者的**全模块**手册：每个按钮、每个功能怎么用，以及它在内部是怎么实现的。
> 与 `AGENT_USER_GUIDE.md`（精简版+使用经验）互补；本文以「功能 → 内部机制」成对展开。
> 适用版本：2026-09-13（含 对话/工作 双模式、图片文件进对话模式、空态输入卡同宽）。

## 0 · 三层架构（先看这张图，后面所有"内部如何"都基于它）

```
浏览器（public/index.html + app.js + app.css）
   │  http://127.0.0.1:4173   Bearer Token 认证（~/.hermes/ui_token）
   ▼
server.js（Node 常驻，LaunchAgent com.hermes-agent.ui）
   │  路由表 lib/router.js + 各领域模块 lib/routes/*.js
   │
   ├─ 对话模式 ──► lib/routes/chatmode.js ──► 直连 Ollama (127.0.0.1:11434)
   │               瘦 prompt、无工具，hermes-chat-8b 模型
   │
   └─ 工作模式 ──► lib/gateway.js ──► Hermes 引擎常驻进程（LaunchAgent com.hermes-agent.gateway）
                   （gateway 不可达时回退 -z 子进程保底）
                                     └─► Ollama：hermes-local-gemma4（视觉/音频同模型）
                                     └─► kb/kb.py（知识库 FTS5 检索）、safety hook、检查点……
```

两条聊天链路的**本质区别**：工作模式把「系统提示 + 全套工具定义 + 知识库召回」都发给模型
（约 1.5 万 token prefill，首字 6.5~18s）；对话模式只有一小段人设 + 最近 20 条消息
（首字 0.2~4s）。这就是侧栏「对话/工作」开关存在的理由。

## 1 · 开始使用

### 1.1 访问与登录
- 浏览器打开 `http://127.0.0.1:4173`（局域网访问：setup 时 `HOST=0.0.0.0`，token 认证已就位）
- 首次弹出令牌框：终端 `cat ~/.hermes/ui_token`，粘贴登录；令牌存在浏览器 localStorage，
  重启不变；服务端令牌文件 `~/.hermes/ui_token`（0600），可用 `HERMES_TOKEN` 环境变量覆盖
- **内部**：所有 `/api/*` 过一道认证闸门（lib/auth.js，Bearer 比对）；静态页面本身不过闸门

### 1.2 服务管理（终端操作）
| 操作 | 命令 |
|---|---|
| 首次安装 | `bash setup.sh`（必须自己跑，LaunchAgent 不能由 AI 装） |
| 重启界面服务 | `launchctl kickstart -k gui/501/com.hermes-agent.ui` |
| 重启引擎网关 | `launchctl kickstart -k gui/501/com.hermes-agent.gateway` |
| 健康检查（31 项） | `bash healthcheck.sh` |
| 备份 | `npm run backup`（仓库 bundle + 引擎侧快照，7 天滚动） |
| 网关意外退出 | 看门狗自动拉起（hermes_startup_watchdog），日志见 `~/Library/Logs/hermes-gateway.*.log` |

## 3 · 侧栏模块

### 3.1 「对话 / 工作」分段开关（新会话按钮下方）
- **干什么**：决定新会话走哪条链路、用哪个模型、历史记到哪边
- **内部**：
  - 前端 `uiSeg` 存 localStorage（`hermes_ui_seg`），切换即换列表；进行中的视图收起新开，原会话留在原列表
  - 对话模式：隐藏工作区栏/模型下拉/放行与自主开关（这些是工作概念）；`POST /api/chat` 带 `mode:'chat'`
  - 服务端 `chatmode.js` 直连 Ollama `/api/chat`（`think:false`，temperature 0.7），
    会话存独立 JSON（`~/.hermes/ui_chat_sessions.json`），与引擎会话天然分列
  - 对话模型 `hermes-chat-8b`（qwen3:8b 包装，num_ctx 8192），与工作模型双驻留（3.2G+3.4G，16G 无压力）
  - SSE 事件契约两边完全一致（ready/session/token/msg/done），前端渲染零改动复用

| | 对话模式 | 工作模式 |
|---|---|---|
| 模型 | hermes-chat-8b（qwen3:8b） | hermes-local-gemma4 |
| 首字延迟（热） | ~0.2-2s | ~6.5s（cache 全命中）~18s |
| 工具/文件执行 | ❌（模型拿不到工具） | ✅ terminal/读写文件/技能全开 |
| 图片 | ✅（gemma4 识别后以文字进对话） | ✅ |
| 文件 | ✅ 小文本内联直传 | ✅ 内联 + 落盘让引擎自读 |
| 知识库召回 | ❌ | ✅（新会话首轮自动注入） |
| 历史存储 | `~/.hermes/ui_chat_sessions.json` | 引擎 state.db |

### 3.2 历史会话列表
- **分组**：今天 / 昨天工作 / 近 7 天 / 更早（对话模式无分组，按更新时间排）
- **搜索**：标题/信息/ID 模糊匹配
- **每条会话操作**：移动到工作区（仅工作模式）/ 重命名 / 导出 Markdown（仅工作模式）/ 删除
- **内部**：工作列表来自引擎 CLI `hermes sessions list`（lib/hermes.js spawn，解析降级时列表照常
  渲染 + 顶部告警，不静默吞错）；对话列表来自 chatstore JSON；消息正文在引擎侧 state.db（SQLite）

### 3.3 工作区栏（仅工作模式）
- **干什么**：给会话贴"项目"标签，侧栏按工作区过滤；新会话自动归入当前所选工作区
- **内部**：独立 JSON 映射（`sessionId → 工作区`），新建归属只在会话首轮写入（assignIfNew，不覆盖）

### 3.4 状态栏（侧栏底部）
- **Ollama 状态 + 驻留模型**：绿点 = 在线，显示当前驻留模型与显存占用（15s 轮询）
- **用量统计**：Σ 24h 请求数、首字均值、tok/s（lib/usage.js 记账）
- **设置入口**：同顶栏 ⚙

## 4 · Composer（输入区）逐功能

| 控件 | 用法 | 内部机制 |
|---|---|---|
| 输入框 | Enter 发送，Shift+Enter 换行 | 客户端 SSE 流式读取（fetch + ReadableStream） |
| 📷 图片 | 选图 → gemma4 识别 → 识别文字并入消息 | `POST /api/vision`（ollama.js multimodalAsk，VISION_MODEL=对话同模型避免换载）；客户端压到最长边 1280 再传 |
| 📎 文件 | 小文本（≤6000 字符）内容直接内联进消息；大文件/项目落盘后把路径交给引擎自读 | 内联：FileReader 直读；落盘：`POST /api/upload` 存 `~/.hermes/uploads/`（24h 清扫）。**对话模式**：只收文本类（无工具读不了路径），超限/二进制弹窗引导切工作模式 |
| 🎙 语音 | 按住说话 → 转文字填入输入框 | `POST /api/transcribe`（gemma4 音频转写，prompt 要求只输出转写文本） |
| 工作区内修改 | 开启后本轮及后续允许高危工具执行（黄区放行） | gateway 路径写会话级放行文件（`ui_bypass_sessions.json`，TTL 5 分钟，到期自动回收）；见 §6 安全 |
| 自主执行 | 无人值守连续干活开关 | `autonomous:true` → 服务端把三色权限/检查点纪律/摘要格式前导注入 prompt（lib/autonomy.js，不动 system prompt 护住缓存前缀） |
| ✨ 优化提示词 | 把口语输入改写成结构化表达（本地模型 3-8s） | `POST /api/optimize`（ollama.js，独立小任务） |
| 折叠/展开 | 思考过程显示/隐藏 | **纯显示开关**，不影响模型行为与速度（2026-09-12 由"快速/思考"更名） |
| 模型选择 | 仅工作模式；本地模型 + 已配置云端 | `/api/models` 与 Ollama 已装列表取交集，防"幽灵模型" |
| 发送/停止 | 忙时按钮变停止 | `POST /api/stop` → 中断 gateway run（abort controller）；断开 SSE 也是兜底中断 |

## 5 · 消息流里的东西

- **Trajectory 三阶段进度**：建连 → 备上下文（prefill）→ 模型推理。原本"空白等待"被拆成可见阶段
- **工具时间线**：模型调 terminal/读文件等时，实时显示调用与结果（DB 轮询 + token 流双通道）
- **停止条件裁判**（lib/stopjudge.js）：服务端观测"原地打转/卡死"，三级 `ok/warn/hard`，
  界面弹警示条。默认**只报告不中断**（`HERMES_JUDGE_ABORT=1` 才强制停）
- **推荐磁贴**：回答结束后后台生成 3 条追问（`/api/suggest`，失败静默）
- **完成提醒**：长任务结束发系统通知
- **会话压缩**：会话太长时 `POST /api/session/compact` → 本地模型生成摘要 → 新会话一次性注入

## 6 · 安全模型（工作模式）

**三色权限**（详见 docs/AUTONOMY_POLICY.md）：
- 🟢 绿区：只读类命令直接执行
- 🟡 黄区：写文件/常规变更 → 需要「工作区内修改」放行（TTL 5 分钟）
- 🔴 红区：明显破坏性命令（rm -rf 等）→ **hard 拦截**，即使开了放行也拦

**内部**：pre_tool_call hook（`hooks/safety_check.py`，fail_closed=true——hook 崩溃也阻断）。
命中红区时 agent 停下输出「⛔ 需要授权」，前端弹审批框，用户批准后重跑。

## 7 · 知识库（KB）与记忆

### 7.1 知识库
- **三分类**：inbox（收集）/ distilled（提炼）/ memory（经验），当前 44 条
- **查看器**：顶栏 📖 或 `/kb` 页面；UI 里输 `/kb 关键词` 也可手动检索（结果以卡片插入对话，不发给模型）
- **自动召回**：工作模式新会话首轮，服务端跑 `kb.py recall`（SQLite FTS5 trigram 全文检索），
  相关性过阈值的经验以「[自动召回的相关历史经验]」前缀注入——这就是老会话懂你的原因
- **沉淀**：Agent 会话里可以让自己"记一条经验"，落 inbox

### 7.2 记忆（工具箱第 4 个 tab）
- 两个文件：`~/.hermes/memory/MEMORY.md`（项目记忆）与 `USER.md`（用户偏好）
- 编辑保存走 `POST /api/memory/save`（只允许写这两个固定路径，≤200KB）
- 引擎每次会话都会把这两个文件带进 system prompt

## 9 · 云端设置（⚙）

- 预设 provider（SiliconFlow 等）+ 自定义 baseURL/key/model；保存到 `~/.hermes/cloud_providers.json`
- 顶栏模型下拉选云端模型时，发送前先做健康检测（`/api/provider/health`），不可达**自动降级本地**并提示
- `POST /api/prewarm`：预热本地模型（空 body generate，只加载驻留不产出）
- 注意：这里的云端密钥只服务**特工自己的聊天**；OpenCode 的云端配置在 `~/.config/opencode/opencode.json`（独立体系，密钥走环境变量 SILICONFLOW_API_KEY）

## 10 · 检查点回退（顶栏 ⏮）

- **干什么**：助手每次改文件前自动留"影子快照"，改坏了可一键还原
- **内部**：引擎写文件前触发（含 terminal.cwd 钉在工作区的前置条件，保证 agent 不会写到家目录）；
  `GET /api/checkpoints/list|plan|diff` 看列表/预案/差异，`POST /api/checkpoints/restore` 回退
- 详见 docs/checkpoints.md

## 12 · 已知边界与常见问题

- **16G 内存**：工作模型 9.6G 单驻留为主；对话/工作双驻留约 6.6G+3.4G 可共存；不要同时再开大模型（OpenCode 测试后记得 `ollama stop`）
- **首字慢**：工作模式新会话 prefill 大是结构性成本；纯闲聊请用对话模式
- **对话模式答不了"帮我改文件"**：它没有工具，这是设计；切工作模式
- **列表报"解析失效"**：引擎 CLI 输出格式变了，列表仍渲染，顶部有重试告警
- **令牌忘了**：`cat ~/.hermes/ui_token`
- **页面提示"界面已更新"**：public/ 下文件有改动，刷新即可（CSS/JS 均 no-cache）
- **启动屏**：打开页面时先显示品牌启动屏（图标+名称+转圈），界面就绪自动淡出。样式内联在
  index.html 里、不依赖 app.css——就算刷新恰好撞上样式文件被写坏，看到的也是优雅的启动屏而非裸 HTML；
  5 秒兜底保证 app.js 加载失败也能进入界面
