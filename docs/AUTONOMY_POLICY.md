# 放手自主执行 · 安全方案

> 目标：让特工在无人值守下连续干活（跑测试、拆任务、批量改文件），同时保证
> **每一次不可逆动作之前都有拦截点，每一次出错都能回滚到已知好状态**。
>
> 方案长在本机既有机制上，不引入新依赖：
> - `hooks/safety_check.py` —— pre_tool_call 拦截钩子（blocklist，fail-closed 兜底）
> - `~/.hermes/ui_bypass_sessions.json` —— 会话级放行，**TTL 默认 5 分钟自动过期**（`HERMES_BYPASS_TTL_MIN` 可调）
> - 前端「工作区内修改」开关 = `allowDangerous` → server 写放行文件
> - 前端 ↑ 停止按钮 = 任何时刻可强制中断

---

## 〇、spec-kit 的触发方式：自动为主，重要任务手动点名

Hermes 是**索引常驻 + 按需全文**的渐进式加载：每轮只注入 `- name: description` 索引（~20 token/技能），
模型自己当路由器，命中后调 `skill_view('spec-kit')` 读全文。所以两种方式都存在：

| 方式 | 怎么触发 | 命中率 | 判断依据 |
|---|---|---|---|
| **自动**（默认） | 任务描述里出现触发词：做计划、拆任务、写个 spec、从想法到落地、spec-driven、按流程做 | 中高（取决于描述质量与小模型状态） | SKILL.md description 已埋 7 组显式触发词，索引每轮常驻；模型读任务后自行匹配并加载 |
| **手动点名** | 输入「用 spec-kit 走一遍：`<功能描述>`」或「加载 spec-kit 技能」 | ≈100% | 技能名直接出现在指令里，模型必然 `skill_view` |

**判断口诀**：
- 任务是**新功能开发 / 重构 / 大改动** → 手动点名（宁可多召回不可漏召回，规划错一次返工 30 分钟）
- 任务是**随手问一句「帮我理理思路」** → 自动命中即可，漏了也不亏
- 想验证是否命中 → 看 Trajectory 里工具时间线有没有 `skill_view(spec-kit)` 一行，没有就是没加载

## 一、总体架构：三层闸门

```
第 1 层  红区硬拦截（safety hook，不可绕过）
         rm -rf 系统目录 / sudo / dd / 格式化 / 关机 …
         → hook 直接 block，模型看到拒绝原因

第 2 层  黄区限时放行（bypass 文件 + TTL）
         工作区内 git commit / 装依赖 / 重启本项目服务
         → 需前端「工作区内修改」确认一次，放行 5 分钟后自动失效
         → TTL 到期 = 自主执行的自然刹车，想继续需再次确认

第 3 层  绿区全自动
         工作区内读写文件、跑测试、git 只读命令、生成文档
         → 无需任何确认，hook 不拦，模型直接执行
```

设计取向：**红区宁可误拦（fail-closed），绿区宁可笑放**；黄区靠 TTL 把自主执行切成
「5 分钟一段、每段之间有自然检查点」的节奏，而不是一条道跑到黑。

## 二、任务范围与权限边界（三色清单）

### 🟢 绿区 — 全自动执行，无需确认
| 允许 | 示例 |
|---|---|
| 工作区内读文件 | `Read` / `cat` / `grep` / `find`（限工作区路径） |
| 工作区内写文件 | 新建/修改代码、文档、spec-kit 产物（spec/plan/tasks.md） |
| 只读命令 | `git status/log/diff`、`ls`、`wc`、`node --test`、`npm test` |
| 运行测试 | 单测、冒烟、lint、构建验证 |
| 调本地服务 | `curl 127.0.0.1`（4173 / 8642 / 11434） |

### 🟡 黄区 — 前端确认一次，5 分钟内有效
| 允许（需确认） | 附加条件 |
|---|---|
| 工作区仓库 `git add/commit` | 只 commit 不 push；commit 信息注明「自主执行」 |
| 项目内依赖安装 | `npm install <具体包>`，禁止 `-g`、禁止批量升级 |
| 重启本项目 launchd 服务 | 仅限 `com.hermes-agent.ui/gateway`（kickstart） |
| 工作区内 `mv/rm` 单个文件 | 先备份到 `.trash-<日期>/`（见 §五） |

### 🔴 红区 — 一律暂停，等人到场（bypass 放行也不许自动过，见 §七-P1）
| 禁止 | 原因 |
|---|---|
| 删除目录 / 通配符删除（`rm -r`、`rm *`） | 不可逆，且 hook blocklist 无法覆盖所有变形 |
| 修改全局配置 | `~/.hermes/config.yaml`、launchd plist、shell rc、系统设置 |
| 工作区外任何写操作 | 工作区是唯一被授权的活动范围 |
| `sudo` / 写 `/etc` `/usr` `/bin` / `dd` / `mkfs` | hook 已拦，二次确认只是提示「别想绕」 |
| 网络下载并执行（`curl \| sh`、`pip install <脚本>`） | 供应链风险；本机 github.com:443 本就被阻断 |
| `git push` / 改 git 历史（`reset --hard`、`force push`） | 影响远端，超出本机边界 |
| 停掉/杀死非本项目进程 | 误杀系统服务 |

## 三、检查点设置（五道闸）

| 检查点 | 时机 | 动作 | 是否等人 |
|---|---|---|---|
| **CP0 任务冻结** | 开工前 | 把目标、验收标准、允许触碰的目录写进任务首条消息（自主执行没有追问机会，目标必须一次说死） | 人写 |
| **CP1 方案闸** | 改动文件预计 > 3 个，或涉及依赖/配置/删文件 | 先产出计划（spec-kit 的 plan/tasks.md 就是现成载体），停下等人点头 | **等人** |
| **CP2 步进闸** | 每完成一个原子任务 | ① 回写 tasks.md 勾选状态 ② `git commit` 一次（= 自动存档点）③ 一句话汇报进度 | 不等 |
| **CP3 红区闸** | 命中红区清单任意一条 | hard stop，说明命中原因 + 建议的人工操作命令，等人执行或明确授权 | **等人** |
| **CP4 时长闸** | 连续执行满 30 分钟 **或** 40 次工具调用 | 自动收尾：汇总已完成/未完成/遗留风险，结束本轮 | 自动停 |

CP2 的 commit 节奏是整个方案的脊柱：**每一步都可回滚，才敢放手**。
CP4 的两个上限取先到者；黄区 TTL 5 分钟在两者之上再加一层自然断点。

## 四、出错时的回滚与恢复

### 4.1 开工前固证（CP0 附带动作）
```bash
git rev-parse HEAD > /tmp/autonomy-baseline.txt   # 记录基线 commit
git status --porcelain                             # 确认工作树干净才开工
```

### 4.2 分级回滚
| 故障等级 | 现象 | 恢复动作 |
|---|---|---|
| L1 单步失败 | 某个命令报错 | 诊断根因 → 一次性修复 → 重跑该步；**同一问题连败 3 次立即停**，带着已试方案等人 |
| L2 多步污染 | 改坏了多个文件 | `git checkout -- <文件>` 或 `git revert <commit>`，逐 commit 回退到最近绿点 |
| L3 全盘失控 | 大范围改坏 / 测试网崩 | `git reset --hard $(cat /tmp/autonomy-baseline.txt)`（红区语义，但此时由人执行或明确授权） |
| L3+ 配置/环境被污染 | 服务起不来 | 恢复 `.bak` 配置 → `bash setup.sh` → `bash healthcheck.sh`；终极兜底 `backup.sh` 的 bundle |

### 4.3 删除类操作的铁律
- 一律 `mv <目标> .trash-<YYYYMMDD>/`，**不真删**；任务结束汇报时列出可清理项，由人决定是否清
- `rm` 只允许出现在绿区临时文件（如 `/tmp` 下自己刚创建的产物）

## 五、时长与影响范围限制

| 维度 | 上限 | 实现方式 |
|---|---|---|
| 单轮自主时长 | 30 分钟（CP4） | 任务 prompt 里写死；前端 Trajectory 计时可见 |
| 工具调用次数 | 40 次 | 同上，超出即收尾汇报 |
| 黄区放行窗口 | 5 分钟/次（现成 TTL） | `HERMES_BYPASS_TTL_MIN`，不调大即维持 |
| 流式看门狗 | 5 分钟无输出自动断 | 现成 `HERMES_STREAM_IDLE_MIN`，防模型死循环烧机 |
| 空间边界 | 仅当前工作区目录 | 任务 prompt 明示 cwd；hook 对工作区外写命令语义拦截 |
| 网络边界 | 仅 127.0.0.1 本地服务 + 明确列出的源 | `curl \| sh` 类在红区 |
| 并发 | 同一时间只跑 1 个自主任务 | 16G 内存 + 单 Ollama，并发=互相抢资源 |
| 影响面申报 | 结束必交清单 | 改了哪些文件、跑了哪些命令、遗留风险，一段话讲完 |

## 六、怎么落地（今天就生效的用法）

**最小用法（零代码改动）**：
1. 发任务时把本方案的约束写进 prompt 开头，例如：
   > 自主执行以下任务，遵守：绿区直接做；每完成一个子任务 git commit 一次；
   > 删除一律移 .trash-20260912/；遇到删目录/改全局配置/装依赖/sudo 立即停下问我；
   > 总时长不超 30 分钟或 40 次工具调用，结束时给清单。任务：…
2. 需要「工作区内修改」能力时点前端开关（= 黄区 5 分钟放行），到期不续
3. 全程盯 Trajectory 时间线，异常直接 ↑ 停止

**P1 改造建议（把红区从"建议"变"硬闸"，~20 行）**：
在 `hooks/safety_check.py` 里把红区清单抽成 `HARD_PATTERNS`（现有 DANGEROUS_PATTERNS
扩展：`rm -r` 不带路径限制、`mv/rm` 通配符、`git push`、`curl|sh`），并让
**bypass 命中 HARD_PATTERNS 时仍返回 block**——放行文件只豁免黄区，不豁免红区。
这一改动把"人确认过一次"和"永久放行"彻底解耦，是自主执行敢放手的关键前提。

**P2 建议（可选，半天）**：CP4 时长闸做成 server 侧强制（chat 路由记 run 开始时间，
超 30min 注入收尾指令），不依赖模型自觉。

## 七、已知残留风险（诚实清单）

1. hook 是 blocklist 而非硬边界：编码变形命令（`bash -c $'…'`、`find / -delete`）可绕过——
   这正是红区清单要求"等人"而非"放行后自动过"的原因
2. 小模型在长自主任务里会漂移目标（遗忘 CP0 冻结的目标）——缓解：tasks.md 每步回写，
   相当于外置记忆；超过 20 步建议拆成多轮
3. 黄区 TTL 到期瞬间若正在执行半截命令，不会被腰斩（hook 只在**下一次**工具调用时生效）——
   可接受，半截命令本身就有 commit 边界保护
