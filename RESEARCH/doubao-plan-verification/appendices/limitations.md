# 局限性与未知

## 已知局限

### 1. 时效性风险（最高优先级）
- 本报告涉及 2026 年新发布的模型（qwen3.5 家族、qwen3-coder）与快速迭代的工具（OpenCode、Hermes）。所有外部结论基于 2026-09-05/06 的检索与页面抓取。
- Ollama 模型标签、OpenCode 配置格式、Hermes CLI 均可能在未来数周内变化。
- 建议：落地前用 `ollama list`、`ollama pull <模型>`、`opencode --version` 实测确认。

### 2. ECC 仓库归属未做 git 级血缘分析
- WorldFlowAI/everything-claude-code 与 affaan-m/everything-claude-code 的关系（镜像？分叉？转移？）仅据双方面 README 与检索结果推断，未做 commit 历史比对。
- 对结论的影响有限（无论归属如何，"npx skills add 非官方推荐路径"成立），但归属叙述可能不够精确。

### 3. 第三方模型未本机实测
- frob/qwen3.5-instruct:9b 等第三方改版的"工具调用弱"结论仅依据其 README 自述，未在用户 16G 机器上实跑验证。
- qwen2.5-coder:14b vs qwen3-coder:30b 在 M4 16G 上的实际编码质量/速度对比未做基准测试。

### 4. 未验证的运行时行为
- Hermes 7B + OpenCode 14B 在同一 16G 机器上**并发**的真实内存峰值未实测（文档与本研究都建议避免并跑，但未量化）。
- OLLAMA_KEEP_ALIVE 放宽后对用户实际工作流（频繁切模型）的内存回收速度未实测。

### 5. 声明选取的完整性
- 本研究聚焦文档中**可证伪的技术声明**（11 条）。文档中的架构理念（"主 Agent + 编码子 Agent 分工"）属设计判断，未做正误判定，仅评估其与本项目现状的吻合度。
